# Анализ присланного `lod_uv1_lightmap.py`

Проверено 2026-10-09 по пользовательскому файлу, Blender add-on 1.1.0,
MIT, spec v1.2. Это анализ кода и отдельных чистых функций, а не запуск
Blender на production-моделях. Оригинал не включён в пакет.

## Как работает алгоритм

1. Извлекает UV0-острова каждого LOD, разрезает mirror/flip seams и проверяет
   вырожденные UV-грани и самопересечения.
2. `build_groups` объединяет острова через положительные пересечения UV0:
   внутри одного LOD и между всеми парами LOD, включая отсутствующие промежуточные LOD.
3. Для группы создаёт общие слоты. Их число равно максимальному числу островов
   этой группы в любом LOD. Начинает с наиболее грубого LOD.
4. `match_pair` оценивает близость 3D-центров и нормалей поверхностей,
   пересекающихся в UV0. Жадно назначает разные слоты островам одного LOD.
5. `write_uv1_packed` применяет к каждому общему слоту одинаковое преобразование
   UV0: единый масштаб и перенос для всех LOD. Прямоугольники слотов упаковывает
   shelf packer, затем проверяет итоговые пересечения.

Это совместное построение атласа всех LOD. Наш GroupedShellTransfer переносит
уже построенный source UV2. Перенос всего подхода потребует перестройки source
атласа и последующего bake; нельзя заменить им только target projection и
считать старый lightmap совместимым.

## Что полезно для Mesh Lab

- **Общая область всех LOD до packing.** Union bbox учитывает границы грубого LOD,
  выходящие за source chart. На DressingTable это может устранить clamp,
  который возникает, когда target выше source примерно на 20%.
- **Разделение физических копий и фрагментов.** Общий UV0 ещё не означает
  одну физическую поверхность. Отдельные копии должны иметь разные слоты;
  фрагменты одной поверхности могут делить слот при отсутствии пересечений.
- **Сопоставление всех пар LOD.** Деталь, исчезнувшая на промежуточном LOD,
  сохраняет связь с остальными уровнями.
- **Проверка до записи и после packing.** Невалидный source должен быть
  виден отдельно от дефекта target projection. Нужны также stretch, density,
  coverage и padding в пикселях — одной проверки overlap недостаточно.

## Проверенные ограничения

### Размер текстуры и texel density

В коде нет метрики размера исходной текстуры. `write_uv1_packed` использует
одинаковый scale для U и V, поэтому сохраняет исходное растяжение. На квадратной
геометрии с UV0 шириной 1 и высотой 0.5, изотропной в текстуре 1024×2048,
в квадратном атласе получается anisotropy 2.0. Исполнение самой функции на
минимальном fixture подтверждает **2.0 → 2.0**.

Единый scale сохраняет уже существующую плотность, но не выравнивает её между
островами. Для нашего варианта сначала нужна texture metric, затем проверка
UV относительно 3D. Исправление только aspect ratio не устраняет произвольное
исходное растяжение или разную плотность островов.

### Жадное назначение не является оптимальным

На двух source-островах с центрами (0,0,0), (0.2,0,0) и двух target-островах
(0.09,0,0), (0,0.11,0), одинаковых UV-треугольниках, `w_pos=1`, `w_normal=0`
и diagonal=1 реальный `match_pair` даёт суммарный score **168.1746**.
Перестановка двух назначений даёт **178.0**. Инъективность предотвращает
совместное использование слота, но не гарантирует правильного соответствия.
Нужен assignment solver либо ограниченный поиск конфликтующих компонент.

Кроме того, пары с score=0 тоже участвуют в жадном назначении. `threshold_min`
выдаёт предупреждение после выбора, а не исключает такую связь.

### Пересечение UV0 не доказывает совпадение texels между LOD

В shortcut `DIRECT_COPY_CONSISTENCY=0.98` измеряется доля площади островов
в группах с несколькими LOD. Она не измеряет координатную ошибку соответствующих
3D-точек. UV0 целого квадратного острова, повёрнутый на 90° в другом LOD,
имеет ту же область: группа остаётся shared singleton, heuristic допускает
direct copy, но lightmap на той же геометрии поворачивается.

`match_pair` взвешивает центры целых target-граней, которые пересекают source
грань, их полной UV-площадью. Он не вычисляет 3D-центр фактического clipped
пересечения, несмотря на формулировку в начале файла. Это важно при очень
разной tessellation и частичном пересечении большой target-грани.

### Запись и validation

В `extract_lod` включённый Merge by Distance записывает welded UV обратно
в исходный UV-канал **до** проверки всей prop. Поэтому заявленное «validation
failure — no UV writes» выполняется для target-канала, но не для source UV0
при включённом merge. Итоговые overlaps после packing записываются в отчёт;
автоматического rollback уже записанного target нет.

Gutter floor 0.001 задан в UV-единицах, а не относительно bake resolution:
около 0.5 texel при 512 и 2 texels при 2048. Last-resort packing может убрать
gutter полностью. Для lightmap это должно быть явным состоянием результата.

## Следующий отдельный benchmark-вариант

Совместный layout имеет смысл проверить как отдельный метод подготовки:
texture metric → проверка source → cross-LOD correspondence → общие области
physical charts → packing всех LOD → одинаковое преобразование → final gate.

Нужно сравнить с текущим transfer на сохранённом корпусе, особенно DressingTable,
Bench/Park_Bench, Shelf reverse, Tire и Train. Проверять не только отсутствие
overlap: геометрическое соответствие, anisotropy, density variation, padding,
atlas utilization и время. Direct-copy shortcut разрешать только после проверки
соответствия по геометрии, а uncertain match сохранять в диагностике.

В текущую production-проекцию этот альтернативный layout не перенесён:
исправления используют существующий source atlas и общую оценку recovery
кандидатов. Локальное воспроизведение чистых функций и его JSON находятся
в `_results~/candidate-quality-20261009/analyze-attached.py` и
`attached-algorithm-analysis.json`; импорт bpy и запись пользовательских моделей
не выполнялись.
