# Завершение геометрического UV-эксперимента

2026-10-04. Закрыта геометрическая фаза chart-merge Experiment #1 / PR #214.
Результат — проверенные baseline и контроль параметризации для следующего этапа
обучения. Подходящего автоматического решения на пользовательском эталоне не
получено; дальнейший перебор merge/relax/числа шелов в этой фазе прекращён.

## Выводы

1. **Расположение швов — отдельная задача.** На одинаковой ручной геометрии
   merge уменьшает количество charts с 76 до 22, но снижает recall нужных
   швов V1 с 50.12% до 30.17%. Zero overlaps и низкий stretch не подтверждают
   художественное качество разрезов.
2. **PartUV и OptCuts действительно запускались.** Полный PartUV с ABF при
   thresholds 1.1/1.25/1.5 даёт seam F1 0.189/0.188/0.145. Его PAMO GPU default
   на GTX 980 Ti не прошёл и не считается успешным тестом. Свободный OptCuts
   даёт F1 0.004; ограничения на части улучшают результат, но не восстанавливают
   авторские границы. Это результат одного бюста, не рейтинг методов вообще.
3. **Relax полезен после выбора разрезов.** Area-bounded piecewise OptCuts
   ограничивает слишком крупные charts и уменьшает дополнительное вытягивание
   UV-треугольников, но F1 остаётся около 0.36. Сам relax не перенесёт шов на
   другой путь по сетке.
4. **Внутренние overlaps требуют полного скана треугольников.** AutoUV cone
   35/50/65 имеет 51/59/42 positive-area пары внутри шеллов при согласованном
   winding. Поэтому проверка ориентации и пересечений разных шеллов недостаточна.
5. **Даже точные cuts не воспроизводят весь ручной результат.** Авторские cuts
   с заново вычисленными SLIM UV дают zero overlaps, но fill 50.45% против
   69.14% у V1. Нужно отдельно исследовать параметризацию, ориентацию, плотность
   и упаковку; ручные UV-координаты не выдавались за предсказание сети.
6. **Source-сигналы нельзя превращать в универсальные веса без проверки.**
   Предыдущий curvature/cavity/AO анализ помог распознавать hard boundaries,
   но не показал преимущества для остальных UV-разрезов. В обучении сравним
   geometry-only и geometry+source на одних независимых splits.

| Контроль на 1856-face геометрии | Seam F1 V1 | Overlap pairs | Triangle fill |
|---|---:|---:|---:|
| Ручной V1 | 1.000 | 0 | 69.14% |
| xatlas | 0.329 | 0 | 55.84% |
| merge | 0.276 | 0 | 54.63% |
| PartUV ABF 1.25 | 0.188 | 0 | 59.47% |
| Piecewise OptCuts cap 20%, Ed 4.15 | 0.361 | 0 | 51.13% |
| AutoUV cone 50 | 0.172 | 59 | 53.42%* |
| Авторские cuts → SLIM → square packing | 1.000** | 0 | 50.45% |

\** Швы заданы эталоном: это контроль solver, не автоматический результат.

## Финальная проверка

[CLOSURE_VALIDATION.json](LearnedSeamResearch/CLOSURE_VALIDATION.json) фиксирует
проверку 22 опубликованных quality rows: 19 различных captures, все исходные
SHA256, точные positions/connectivity и oriented face correspondence совпали.
Для 18 captures заново выполнен полный intersection scan, включая соседние
треугольники одного chart; quality metrics совпали с опубликованными CSV.
Заново проверены 26 length-weighted seam V1 rows и наличие отдельных UV PNG;
в JSON сохранены SHA256 опубликованных изображений.

Повторный Python-прогон до добавления trainer: SeamPlacementBenchmark —
18 passed; LearnedSeamBenchmark — 21 passed / 1 skipped. Пропущен symlink
fixture из-за Windows WinError 1314; реальная junction-проверка прошла.
Полная старая галерея 221 layout, сами сторонние solvers и Unity EditMode tests
заново не запускались. Production Editor/Native~/Plugins/defaults не менялись
в этой завершающей проверке. Исправлено только описание stretch в старом
отчёте: это отношение сингулярных значений, не их квадратов; числа прежние.

## Переход к обучению

Добавлены `train.py` и 8 contract tests. Итоговый LearnedSeamBenchmark:
29 passed / 1 Windows symlink fixture skipped. На GTX 980 Ti выполнены два
synthetic CUDA runs полной width-64 / 4-block модели: 4 эпохи непрерывно и
2 эпохи + resume до 4. Model, optimizer и итоговые metrics совпали точно;
partial run не оценивал test. Проверено восстановление финального JSON без
повторного test и отказ одному unassigned бюсту до создания run directory.
[Численные доказательства и SHA финальной версии](LearnedSeamResearch/TRAINER_VALIDATION.json).
Это переход к исполнимому обучению, а не подтверждение качества на реальных UV.

Первый baseline предсказывает вероятность UV-шва на геометрическом графе.
Сглаживание, изменение topology и decoder валидных цепочек/дисковых patches
будут проверяться отдельно. Классификация рёбер сама по себе ещё не unwrap.
Начальный исполнимый trainer оценивает два geometry features; это контроль
для последующего расширения признаков и сравнения с предобученным энкодером.

Два текущих UV-варианта бюста имеют одинаковую геометрию и входные features,
но разные labels на 88 рёбрах из 2784. Это один независимый asset, а не два
обучающих объекта. Без условного задания стиля нельзя требовать, чтобы одна
детерминированная сеть точно восстановила оба варианта. Бюст сохраняется как
ручной контроль; quality training требует независимых train/val/test families.
V1 проходит overlap scan; у V2 известны 16 positive-area overlap pairs внутри
двух charts. Его seam labels можно анализировать как другой вариант cuts,
но весь V2 atlas нельзя считать сертифицированным эталоном без исправления.

В первом цикле фиксируются split и hashes, normalization только по train,
выбор best checkpoint только по val и отдельный test после окончания обучения.
Проверка checkpoint/resume на синтетических fixtures подтверждает работу
trainer, но не качество швов на пользовательских моделях. RTX 3070 Ti находится
на другом ноутбуке: его время обучения и VRAM этим экспериментом не измерены.

Правила сбора исходных high→handmade low, сохранения UV/SG/текстур и предотвращения
утечек: [UV_LEARNED_SEAMS.md](UV_LEARNED_SEAMS.md).
